# MedVault — Medical Store Management System

## Project Overview
MedVault is a 3-tier **monolithic** medical-store app (inventory, expiry and stock tracking) built as a DevOps portfolio project. It is intentionally not microservices yet.

## Features
Dashboard (totals, value, low/out-of-stock, expired, expiring soon) · Medicine CRUD · dynamic status calculation · search (name/company/batch/category) · filters · sorting · seed data (21 medicines incl. low, out-of-stock, expired, expiring-soon) · toasts, loading/empty/error states, delete confirmation, responsive UI.

## Architecture
```text
Application            Docker                    Kubernetes
React                  Frontend Container        Frontend Deployment (NodePort)
 ↓                            ↓                         ↓
Node.js / Express      Backend Container         Backend Deployment (ClusterIP)
 ↓                            ↓                         ↓
MongoDB                MongoDB Container         MongoDB StatefulSet
                                                        ↓
                                                 PersistentVolume (PVC)
```
Browser -> Nginx (frontend) -> `/api/` proxied to backend -> MongoDB.

## Technology Stack
React 18, Vite, React Router, Axios, plain CSS · Node 20, Express, Mongoose, Helmet, CORS, dotenv · MongoDB 7 (Docker only) · Nginx · Jest/Supertest · Docker Compose, Kubernetes, Helm.

## Environment Variables
| Where | Variable | Purpose |
|---|---|---|
| Backend | `PORT`, `MONGO_URI`, `CORS_ORIGIN` (comma list or `*`), `NODE_ENV`, `AUTO_SEED` | see `backend/.env.example` |
| Frontend (dev) | `VITE_API_URL` | see `frontend/.env.example` |
| Frontend (container) | `API_URL`, `BACKEND_UPSTREAM` | runtime, no rebuild needed |
| Compose | `FRONTEND_PORT`, `BACKEND_PORT`, `API_URL`, `CORS_ORIGIN` | root `.env.example` |

**Frontend API URL approach.** Vite embeds `VITE_*` at build time, which would force a rebuild per environment. So the API client resolves its URL as: runtime `window.__APP_CONFIG__.API_URL` (file `/config.js`, regenerated by the Nginx container at start from `API_URL`) → `VITE_API_URL` (dev) → `/api`. The default `/api` is same-origin: Nginx proxies it to `BACKEND_UPSTREAM`, so the same image works in Compose, Kubernetes and AWS. To point browsers at a separate public API, set `API_URL=https://api.example.com/api` (and `CORS_ORIGIN` on the backend). No source edits, no rebuild.

## Local Development (Mode 1: React + Node local, MongoDB in Docker)
```bash
docker compose up -d mongodb
cd backend && cp .env.example .env && npm install && npm run seed && npm run dev
cd frontend && cp .env.example .env && npm install && npm run dev
```
Open http://localhost:5173. Tests: `cd backend && npm test`. Lint: `npm run lint`.

## MongoDB Docker Setup
MongoDB is never installed on the host. Compose runs `mongo:7` with named volume `medvault-mongodb-data`, published only on `127.0.0.1:27017`.

## Docker Compose (Mode 2: everything in containers)
```bash
docker compose up -d --build   # http://localhost:8080 (data auto-seeded when empty)
docker compose ps
docker compose logs -f
docker compose down            # stops/removes containers; data KEPT
docker compose down -v         # ALSO deletes volumes => database wiped
```
Data survives `restart` and `down` because it lives in the named volume; only `-v` removes it. Services talk via service names (`backend -> mongodb:27017`) on the `medvault-net` network.

## Docker Images
```bash
docker build -t medvault-backend:latest  ./backend
```

## Kubernetes Deployment
Build images so your cluster can see them (Docker Desktop: shared automatically; minikube: `minikube image load medvault-backend:latest medvault-frontend:latest`; kind: `kind load docker-image ...`).
```bash
kubectl apply -f k8s/namespace.yaml
kubectl apply -f k8s/
kubectl get pods -n medvault
kubectl get svc  -n medvault
kubectl get pvc  -n medvault
kubectl logs <pod> -n medvault
kubectl describe pod <pod> -n medvault
```
Access: NodePort **30080** → http://localhost:30080 (Docker Desktop) or `minikube service frontend-service -n medvault --url`. For AWS change `frontend-service` type to `LoadBalancer` (Helm: `--set frontend.service.type=LoadBalancer`).

**Browser vs cluster networking:** React runs in the browser, so it cannot use `backend-service` (ClusterIP DNS). The browser only calls the frontend NodePort at `/api`; Nginx inside the cluster forwards to `backend-service:5000` (from ConfigMap `BACKEND_UPSTREAM`). The backend reaches MongoDB via `MONGO_URI` (Secret) → `mongodb-service`.

`k8s/secret.yaml` holds **dev placeholder** credentials; replace before any shared use.

## Helm Deployment
```bash
helm lint ./helm/medvault
helm install medvault ./helm/medvault
helm list
helm status medvault
helm upgrade medvault ./helm/medvault --set backend.replicas=2
helm uninstall medvault
```
Image repos/tags, replicas, service types, ports, `environment.*` and Mongo credentials are in `values.yaml`, e.g. `--set backend.image.repository=YOUR_DOCKERHUB_USERNAME/medvault-backend --set mongodb.auth.password=...`. `namespace.create=true` creates the namespace; use k8s/ **or** Helm, not both at once.

## API Documentation
| Method | Path | Notes |
|---|---|---|
| GET | `/api/health` | `{status, service, database}`; 503 if DB down |
| GET | `/api/medicines` | query: `q`, `status` (all/available/low-stock/out-of-stock/expired/expiring-soon), `sortBy` (name/price/quantity/expiry), `order` |
| GET | `/api/medicines/search?q=` | same handler as list |
| GET | `/api/medicines/stats` | dashboard totals |
| GET/PUT/DELETE | `/api/medicines/:id` | 404 if missing |
| POST | `/api/medicines` | 201; 400 validation; 409 duplicate batch |

Responses: `{success, data, message?, errors?}`. Each medicine includes computed `status`, `statusLabel`, `statuses`.

## Database Seeding
```bash
cd backend && npm run seed              # skips if data exists
npm run seed -- --force                 # wipe and reseed
docker compose exec backend npm run seed
```
`AUTO_SEED=true` (set in Compose/K8s/Helm) seeds only when the collection is empty.

## Troubleshooting
- **MongoDB connection error**: inside Docker/K8s use the service name (`mongodb`, `mongodb-service`), never `localhost`. The backend retries for ~45s at start-up.
- **Backend unavailable**: `docker logs medvault-backend` / `kubectl logs deploy/backend -n medvault`; check `/api/health`.
- **Frontend cannot reach backend**: open `/config.js` in the browser to see the API URL in use; confirm the `BACKEND_UPSTREAM` host/port, that backend Service exists, and that the URL is reachable *from the browser*.
- **Data disappeared**: `docker compose down -v` deletes the volume; in K8s check `kubectl get pvc -n medvault` (deleting the namespace/PVC deletes data). Changing Mongo credentials after first init has no effect on an existing volume.
- **Pods not starting**: `kubectl get pods`, `kubectl describe pod <pod>`, `kubectl logs <pod>`; `ImagePullBackOff` usually means the local image was not loaded into the cluster.
